# 青行 Qingxing · 校园共享自行车数据库系统

在本机实际运行的 React + Express + MySQL 数据库课程系统，包含学生骑行、管理员运营、运维任务，以及截图要求的八个实体、十一项命名联系和七项创新功能。

登录身份会同时影响前端功能入口、后端接口权限和数据范围，并非只隐藏菜单。三种身份使用同一套前端构建产物：学生只能读写自己的骑行、支付、还车记录和个人榜单设置；运维员可处理分配给自己的调度、维修与风险任务；管理员可查看全局分析并管理车辆、停车区、道路、人员和复核流程。后端会在每次受保护请求及写事务中重新校验账号状态和角色，直接调用无权接口同样会返回 403。

项目路径 D:\code\mysqpll。应用端口 5188，开发端口 5189，专用 MySQL 端口 3377，MySQL 数据目录 .runtime/mysql-data。项目脚本核对进程路径，不停止电脑原有 MySQL80 / 3306 服务。

## 已实现功能

- 北航学院路校区离线可交互地图：按官方平面图整理主楼、图书馆、合一楼、新主楼、体育馆等地标；6 个演示停车区、66 辆自行车、真实库存与预留车位。
- 借车→骑行→围栏归还→模拟支付→积分记账；圈外、关闭或满位还车失败保留尝试记录。
- 个人订单、状态筛选、CSV 导出、支付记录、模拟减排与积分流水。
- 故障报修→管理员分配→运维维修完成；故障车辆停止出租。
- 调度建议→管理员确认任务→分配→出发→完成入库；待执行任务可取消。
- 停车区、车辆、员工及用户状态管理；修改容量、岗位、账户状态时检查未完业务。
- 数据库设计页展示真实表字段/约束标识、记录数、联系和数据库对象；触发器名称来自初始化时用管理账号核验的只读目录，运行账号没有建表/触发器权限。

| 图片中的创新点 | 实现 |
|---|---|
| 热点区域分析 | 近7/30日或自定义日期、工作日/周末、小时和站点筛选；缺车、满车、净流量与快照覆盖 |
| 车辆调度建议 | 将库存、需求窗口、目标库存、原因和算法版本保存；确认前重新校验并关联正式任务 |
| 车辆故障风险预警 | 版本化规则评分、结构化原因、去重指纹；支持确认、生成维修工单、解决或撤销 |
| 路线推荐 | 有向且可关闭/禁骑的路网；三模式并排比较，并解释坡度、路面、遮阴、照明与交通属性 |
| 碳积分 | 异常行程先复核；发放与调整使用不可覆盖的有符号流水，保留系数、规则版本及原因 |
| 校园骑行排行榜 | 默认私密、自愿公开昵称；北京时间周/月、并列同名次，私密用户仍能看到“我的名次” |
| 电子围栏还车 | 同时核验坐标、定位采集时间、来源、围栏与容量；失败证据可由管理员复核 |

八个核心实体是用户、单车、停车区、骑行订单、支付记录、运维人员、调度任务、维修工单。物理设计有 **18张表、4个视图、2个触发器、1个存储过程**：一张调度车辆关联表实现 M:N，九张支持表保存路网、采样、拒还复核、调度建议、风险告警、碳积分流水、审计与参数。`carbon_ledger` 是兼容旧查询的只读视图，规范记账表为 `carbon_transactions`。

## 演示建议

1. 用学生账户借车，在“骑行与归还”输入圈外坐标，验证订单仍在骑行。

6. 打开课程报告，运行 SQL 查询或一致性检查，说明事务与约束。

价格：每开始30分钟100分，至少100分。里程由归还时服务器根据路网计算，客户端不能自报任意里程；同站归还估算里程为0，因此不产生积分。未支付订单阻止再次借车。同一用户/车辆不能有两笔活动订单。调度创建时预留车辆与目标车位，运输中车辆无当前停车区；运输中任务必须完成入库，不能直接取消回源。

## 开发和验证

需要 Node.js 22.12+ 和 MySQL 8.0.16+。本机已有 Node 24.16.0 / MySQL 8.0.43。MySQL不在默认目录时设置 MYSQL_BASE；启动脚本会创建专用数据目录、随机凭据和两个独立校园数据库。不要把示例口令占位符直接用作本机 .env。

```powershell
npm ci
& .\scripts\start.ps1 -NoBrowser
npm run db:seed
npm run dev
npm run build
npm test
npm run db:migrate
$env:QINGXING_E2E_URL = 'http://127.0.0.1:5188'
npm run test:e2e
npm run check
node scripts/run-queries.mjs
npm run report
npm run screenshots
```

`npm run db:seed` 是可单独使用的本机数据库初始化命令：它会启动项目专用 MySQL，生成本机 `.env`，依次建表、迁移并幂等写入演示数据。`node scripts/seed.mjs` 只是上述流程的最后一步，要求 3377 端口数据库和表结构已经就绪；新下载目录不要跳过前置步骤直接执行它。

集成测试明确限制在 **campus_bike_test**，重建其中的测试数据；不重置 **campus_bike**。浏览器测试会在演示账户下产生已完成的测试行程、工单、调度和还车尝试。服务端源码修改后需停止再启动；前端修改后运行 build。运行中的应用每分钟采集一次库存，停机期间没有实际快照，不把缺采当作正常。

## 备份和恢复

```powershell
npm run backup
# 将文件名替换为上一步输出的路径；目标库必须尚不存在
node scripts/restore.mjs 'D:\code\mysqpll\backups\campus_bike-时间戳.sql' campus_bike_restore_demo
node scripts/check.mjs campus_bike_restore_demo
```

恢复程序只允许新建 campus_bike_restore_ 前缀库，拒绝覆盖已有库。运行时业务账号 qingxing_app 只有校园库的 DML/EXECUTE 权限，建库、DDL、测试和备份由本机管理凭据负责。.env 不进入交付压缩包。

旧主题数据库 mysqpll 保留；旧源码在 backups/legacy-web3-source-20261004.zip，旧SQL备份在 backups/mysqpll-2026-10-04T09-29-09-104Z.sql。备份目录中的旧材料不是当前提交版本。

## 数据来源和边界

校园地图参考[北京航空航天大学学院路校区官方地图](https://www.buaa.edu.cn/xygk/xydt1/xylxq.htm)整理建筑和道路的相对方位，以米为单位构建本地示意路网。建筑轮廓、停车点和路线长度用于课程演示，不是测绘成果或真实导航；系统没有真实GPS定位、硬件锁或在线地图。安全/舒适权重为教学设定，故障分数是可解释规则，不是训练得到的故障概率。支付、碳系数和积分均为模拟，不连接支付平台。

种子历史订单和标为 DEMO 的库存快照是合成课堂样本；运行后库存快照标为 LIVE。缺满车时长只按相邻且间隔不超过5分钟的快照估计。并发保护使用数据库命名锁串行化写事务，适合课程规模；不声称具备生产平台吞吐能力。自行绕过API写数据库必须遵守相同业务约束。

参考 [Rivertxx/lushu](https://github.com/Rivertxx/lushu) 的路线/关联建模，以及 [BUAA-Database-Shared-Bicycle](https://github.com/oNya685/BUAA-Database-Shared-Bicycle) 的停车区、调度和数据库设计。具体源码参考记录在对照文档。所引用旧聊天完整历史与课程PPT未能通过当前工具取得；本次对齐三张图片、可见聊天摘要和已有课程报告，不声称逐页核对PPT。

## 故障排查

- 服务连接失败：查看 .runtime/app-error.log 与 .runtime/mysql-error.log，确认端口3377和5188。
- 单独运行种子脚本报 `ECONNREFUSED` 或缺表：在项目根目录改用 `npm run db:seed`；它会补齐数据库启动、凭据、结构和迁移步骤。
- 出现 Node.js 语法或 Vite 启动错误：运行 `node --version`，确认版本不低于 22.12。
- 端口被其它程序占用：脚本报错退出，请确认占用方，不要强制停止无关服务。
- 归还失败：查看围栏坐标、停车区开放状态及含预留的剩余容量；订单保留，可换站重试。
- 员工无法执行：确认员工在岗、岗位匹配，任务已分配给该登录人员。
- 容量、账号或岗位修改被拒：先处理相关未完成业务，页面会给出错误原因。
