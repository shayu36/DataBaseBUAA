# 管理端事务与约束

`server/admin.mjs` 提供 saveZone、saveBike、saveStaff、setUserStatus，均先校验 ADMIN 身份及 Zod 输入，再进入与骑行/调度相同的 ledgerTransaction 命名锁事务，写入审计日志。重复名称、编号、邮箱或手机号统一返回 DUPLICATE。所有失败回滚，审计不记录密码或密码摘要。

停车区容量不得小于 occupied + reserved。关闭或调整坐标/围栏半径要求无占用车辆、无预留车位且无源站/目标站活动调度；移动还要求无以该站为起点的进行中骑行。修改同步 road_nodes 名称/坐标，移动同步关联边的欧氏距离。新建站点同时创建路网节点，以四舍五入的米数连接最近旧节点，安全/舒适成本为1；同坐标边保底1米，首个节点无需边。

车辆只能创建为 AVAILABLE/RETIRED；现有 RIDING、MAINTENANCE、DISPATCHING 车辆不可编辑。AVAILABLE 要求开放站点，计入调度预留后的容量检查；同站编辑减去车辆自身已有占位。退役清空当前站点，重新投放再次检查容量。投放日期须为 YYYY-MM-DD、真实公历日期且不晚于北京时间今天；省略新车日期默认今天，省略旧车日期保留原值。

员工新建独立 OPERATOR 账户，使用 bcrypt 10轮摘要；新建必须提供密码，更新可省略以保留摘要。创建不能通过现有邮箱/手机号提升学生权限，更新只操作 staff 已关联的 OPERATOR 账户，同步姓名、电话、邮箱。邮箱/电话使用 users 唯一约束。存在活动调度或未完成已分配维修时不能离岗；有任务时不能更改为不支持该任务的岗位。

账号停用不改变角色。管理员不能停用自己；存在 RUNNING 或 UNPAID 订单的用户不能被停用，须先归还并支付，避免账户停用阻断结算。员工有活动已分配任务或未完成工单时不能停用。普通空闲账户可停用或恢复。

验证：`node --test tests/admin.test.mjs` 使用专用 campus_bike_test 数据库，启动前明确验证库名并建立真实 MySQL schema。测试用例覆盖权限、站点容量/预留/几何/路网、严格日期、退役及重新投放、各活动车辆状态、邮箱冲突不提升权限、bcrypt、任务与工单离岗限制、重复手机号回滚、自停用/骑行/未付款限制和状态变更不升级角色。此测试会清空专用测试库，不能与其它使用该库的测试并行执行。
