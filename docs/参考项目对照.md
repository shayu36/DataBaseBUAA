# 参考项目对照与实现边界

本次查阅本地克隆 .runtime/references/lushu 和 .runtime/references/shared-bicycle 的 README/SQL。引用用于设计分析，没有把参考项目代码直接改名搬入当前实现。

| 来源与检查位置 | 观察到的设计 | 青行的选择及理由 |
|---|---|---|
| [路书 README](https://github.com/Rivertxx/lushu/blob/master/README.md) | 北航2020数据库作业，面向自行车社团活动和路线 | 青行面向共享单车借还、容量、调度、故障，不套用社团活动主体 |
| [路书 road_book.sql](https://github.com/Rivertxx/lushu/blob/master/road_book.sql) | routes 记录起终点、mileage、road_condition；keypoints 固定列；participants 复合主键 | road_nodes/road_edges 将道路拓扑独立建模，Dijkstra依据边权找路线；dispatch_bikes 使用复合主键消除重复关联 |
| 同一 SQL 的 rights 与触发器 | 用户权限单独表；存在显式删除相关记录的触发器 | users 统一认证角色，staff 为独立运维档案；历史外键限制删除，以停用/报废保存记录；密码摘要不采用示例明文结构 |
| [共享单车 01_init_database.sql](https://github.com/oNya685/BUAA-Database-Shared-Bicycle/blob/main/scripts/01_init_database.sql) | parking_areas 使用 POLYGON/SPATIAL INDEX，bikes 使用 POINT；订单与调度人员建模 | 青行使用圆心/半径和米制本地平面示意，明确不是真实GIS；加入维修、碳账本、库存采样与拒还留痕 |
| [05_dispatch_task_procedure.sql](https://github.com/oNya685/BUAA-Database-Shared-Bicycle/blob/main/scripts/05_dispatch_task_procedure.sql) | 依据利用率生成调度、游标锁候选车辆，active_task_id关联任务 | 青行输出可解释建议再由管理员确认，任务车辆M:N保留历史，目标站预留位置防止归还抢占；采用应用事务统筹状态 |
| [07_pay_order_procedure.sql](https://github.com/oNya685/BUAA-Database-Shared-Bicycle/blob/main/scripts/07_pay_order_procedure.sql) | 支付流程以存储过程组织 | 青行应用支付事务、唯一订单/幂等键、支付守卫触发器和订单积分唯一账本组合；仅采样采用存储过程 |

参考仓库中初始化 SQL 含 DROP TABLE / 全局设置，不在当前数据库直接执行。比较是静态源码观察，不表示参考项目已启动或性能优于青行。路线、安全和减排能力均只报告实际实现，不移植参考项目的宣传指标。

其他依据：用户截图、引用会话缓存摘要、旧报告四人分工。引用会话完整正文和课程PPT原文不可取得，不能声称逐页遵循或核验评分细则。
