# 测试与验收说明

测试应在本机 MySQL 已启动且 `.env` 配置完成后执行。`npm test` 会重建 `campus_bike_test` 的测试数据；浏览器测试会在业务演示库中产生测试记录。

交付包筛选测试使用 `uv run python -m unittest discover -s tests -p package_project_test.py`，在临时目录验证配置文件、日志、符号链接及凭据扫描，不修改现有交付包。

```text
npm run build
npm run format:check
npm test
npm start
npm run test:e2e
npm run check
```

浏览器测试需要另一个终端中保持 `npm start` 运行。备份与恢复需要本机 `mysql`、`mysqldump`，操作步骤见项目根目录说明。

## 热点查询样本性能

在隔离测试库中生成 6 个站点、每站 30 天每分钟一条的模拟快照，共 259,200 条。相同环境下，热点报表单次运行由约 8.8 秒降至约 5.8 秒，返回 6,876 个保留可借数量极值的曲线点；统计仍使用全部快照。测试结束后已删除临时测试库。该结果是本机单次对比，不代表生产负载或并发能力。

2026-10-27 增加曲线缺口识别后，在隔离库以 6 个站点、共 259,200 条连续采样作单次对比：增加前约 5.6 秒，增加后约 8.0 秒，均返回 3,600 个曲线点；增加的时间用于按完整采样计算连续段。该结果仅反映本机单次测试，不代表并发吞吐。

生成调度建议的需求读取在隔离库单次对比：6 个站点、259,200 条快照、2,000 笔模拟订单下，完整热点报表约 7.65 秒，仅查询库存和借还需求约 12 毫秒，两者需求和建议一致。该结果不包括建议写入耗时，不能代表生产并发性能。

2026-10-27 进一步复用覆盖时长查询已读取的快照计算数量，在隔离库对 259,200 条快照交替运行三轮：旧版为 7.742、7.803、7.760 秒，新版为 7.308、7.357、7.279 秒；每轮曲线和统计结果一致。该对比为本机样本，不代表生产并发性能。

2026-10-27 将借还汇总、峰值时段及覆盖率计算移至 MySQL 后，在隔离库使用 6 个站点、259,200 条快照和 20,000 笔订单交替运行三轮，旧版约 7.995、7.750、7.706 秒，新版约 7.360、7.468、7.916 秒；每轮报表结果和 6,985 个曲线点一致。需求简版单次为旧版 117.6 毫秒、新版 120.5 毫秒。该样本未显示稳定的耗时差异，不代表生产负载；另外新增了十进制半入边界测试。

2026-10-28 将站点关联和时段补零移入 MySQL，在隔离库用 6 个站点、60,000 条快照和 20,000 笔订单各执行三次：原过程约 1,628、1,513、1,541 毫秒，新过程约 1,589、1,569、1,529 毫秒；站点统计、总覆盖率及 4,392 个曲线点一致。在另一个无快照的 1,000 站点、1,000 笔订单样本中，原过程约 28、21、20 毫秒，新过程约 40、35、33 毫秒，借还统计一致。两组均为过程查询时间，不包括旧版后端结果整理或生产并发；临时库已删除。

调度历史查询在隔离库使用 100 条任务、每条 100 辆车交替运行三轮：旧查询及后端排序约 15、12、13 毫秒；数据库排序及长度校验约 21、19、19 毫秒，返回结果一致。该样本中后者增加约 6–7 毫秒；这不是生产并发测试。另验证会话聚合长度限制很小时，200 个历史车辆编号仍完整有序返回，空列表也正确返回。

## 风险刷新样本性能

此前在隔离库以 10 辆车、10,000 条历史工单进行单次测试，评分结果一致。旧版评分与工单读取约 28 毫秒，向后端传输 10,000 条工单；当时的改进版评分约 10 毫秒，首次完整刷新约 40 毫秒并传输新告警所需的 1,000 条工单，重复完整刷新约 21 毫秒并传输 0 条工单。现版直接在数据库内关联工单，不传输这些工单明细。完整刷新包含告警去重和写入，与单纯读取不能直接比较；结果仅反映本机单次测试。

2026-10-28 在本机 MySQL 上用递归序列单独比较有序工单编号聚合：500、1,000、2,000、4,000 条记录，窗口聚合分别约 25、74、260、1,011 毫秒；有序集合聚合约 6、3、7、6 毫秒，条目数一致。该测试不含表读取或告警写入，不代表完整刷新耗时或生产并发性能。新实现按查询临时提高聚合长度上限，保存前核对数量，防止截断后静默写入；另验证会话上限很小时仍能完整保存 200 条有序编号且不修改原会话设置。

风险原因仅包含五种固定故障类型和三类固定规则说明，原因聚合使用 4,096 字节的查询级上限。测试覆盖五种故障均复发、异常短行程以及低会话聚合上限，确认原因和排序完整且不改变会话设置。

在另一个隔离样本中，10 辆车共有 50,000 条近期工单。交替运行三轮风险评分：旧查询约 155、153、154 毫秒，新查询及后端结果整理约 92、88、88 毫秒；评分和重复故障原因顺序一致。该测试不含告警写入，结果仅反映本机样本。

2026-10-28 使用隔离库的 10 辆车和 50,000 条近期工单，对比将原因整理移入 MySQL 前后的查询，各执行三次：原查询约 86、84、84 毫秒，包含数据库内原因整理的新查询约 92、85、85 毫秒；评分和原因顺序一致。原查询计时不包含后端整理，以上结果未显示稳定的耗时变化，且不包含告警写入或生产并发。

2026-10-28 在隔离库用 10,000 辆模拟车辆（其中 100 辆达到告警阈值）对比完整评分和候选查询，交替执行三次：完整评分约 286、246、248 毫秒，候选查询约 75、73、73 毫秒；候选结果与完整评分筛选结果一致，评估总数均为 10,000。序列化后的结果分别约 1,958,089 和 19,485 字节；这是该样本的应用数据大小，并非网络流量测量。测试不包含告警保存和生产并发，临时库已删除。
