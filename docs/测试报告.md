# 测试与验收说明

## 运行前提与命令

在项目根目录配置 `.env` 并启动本机 MySQL。后端和数据库测试会重建 `campus_bike_test` 中的测试数据；浏览器测试会在演示库中创建骑行、支付、维修、调度、拒还和积分记录。运行前应核对数据库目标并按 [README](../README.md) 备份已有数据。

```text
npm run build
npm run format:check
npm test
npm start
```

保持 `npm start` 运行，在另一个终端执行：

```text
npm run test:e2e
npm run check
```

可选的交付包测试和生成命令需要 Python 与 uv：

```text
uv run python -m unittest discover -s tests -p package_project_test.py
uv run python scripts/package-project.py
```

备份、恢复、教学查询及环境配置的详细操作见 [README](../README.md)。浏览器测试默认通过开发代理访问本机后端；设置 `QINGXING_E2E_URL` 可针对已构建并启动的服务测试。

## 关键边界验证

- 模拟位置以选择归还站点时的时间提交；过期时保留骑行订单并记录拒还原因，重新采集后可继续归还。设备 GPS 来源缺少时间或传入 null 时会被数据库拒绝，且不写入拒还记录；页面本身不读取真实 GPS。
- 对已支付订单使用原支付编号返回原结果；使用新编号返回已支付错误，已用于另一订单的编号返回幂等冲突。积分调整响应丢失后，当前标签页保留原请求供重试；关闭标签页或放弃重试前应核对流水。
- 非法碳规则及超出流水字段范围的新增发放会使相关事务回滚；已有发放的历史复核保留原值。测试覆盖非严格 SQL 模式、科学计数法、除法精度及十进制舍入边界。
- 在独立 MySQL 实例中，已有应用账号密码错误时初始化失败，库级权限保持不变；密码正确及创建新账号时可完成授权。过程源码摘要只记录项目安装的源码，不检测外部手工修改的数据库对象。
- 触发器目录保存在数据库中；受限业务账号可读取核验快照，快照缺失时页面显示未核验。隔离库验证了配置名称冲突及并发修改时保留已有数据，并验证备份恢复后仍可读取快照；外部修改触发器后应重新迁移核验。
- 地图路网图层按需读取数据库快照，区分开放、关闭与禁行路段；测试覆盖未登录访问、加载失败重试、数据刷新和过期请求不覆盖新结果。MySQL 空间判断还覆盖穿越或接触禁行区的道路、站点新建与移动，以及旧库中位于禁行区的站点禁止借车；道路原始状态保留。
- 禁行站点不能新增可借车辆或接收新调度任务，建议生成也排除该目标；测试同时验证既有车辆仍可编辑、调出，已在途任务仍可完成。
- 禁行站点的少量可用车辆也会优先纳入调出建议；测试覆盖与普通供给竞争、建议保存和确认，历史建议版本不重写。
- 建议批量保存测试覆盖空列表、每 100 条的分块边界、不连续编号、接近无符号整数上限的编号及中途失败回滚。
- 仪表盘同时返回原始库存和实际可借数，关闭或禁行站点不计入可借总数；测试覆盖地图、借车列表和已有数据保留。
- 还车测试覆盖禁行目标站与路网节点不一致的旧数据，验证拒绝后订单和车辆状态不变；旧行程仍可返回原禁行出发站，页面同时限制不允许的目标。
- 新库初始化测试逐条比较路段方向与禁行状态，并比对数据库路线和地图定义的路线；模拟已有库禁行状态差异时，检查和受限账号启动均给出提示，且不修改道路。
- 资源缓存测试核对带指纹文件、普通静态文件和接口的响应头；生产服务的浏览器测试验证底图第二次加载未传输文件。当前前端随地图组件立即加载底图，长内容和部分地图区域默认收起，可由用户展开；加载失败时显示提示。开发服务使用 Vite 的缓存策略，生产缓存专项测试在生产入口单独执行。
- 备份在结构锁保护下使用 InnoDB 一致性快照；曾将演示备份恢复到独立新库，核对当时版本、数据库对象和 15 项不变量后删除测试库。只可恢复可信备份，恢复目标不得覆盖现有库。
- 原业务库不存在时，使用项目实际备份在独立新库完成恢复，核对 18 表、4 视图、2 触发器、39 过程和 15 项不变量；另验证重复恢复不会覆盖目标库。测试目标库已清理。
- 热点曲线抽样使用数据库数值排序键；对重复时间、极值、稀疏数据、接近无符号整数上限的编号、远期日期和筛选边界进行新旧查询对照，并用独立参考计算核对抽样结果。
- 不超过 1200 条的站点保留全部曲线数据；测试覆盖 1200 条和 1201 条边界、采样缺口，以及同一报表中稀疏与密集站点和大编号混合。
- 快照采集测试在隔离库中模拟慢数据库：同一进程的重叠周期只保留一次采集；启动或周期采集中触发退出处理后，释放数据库锁可完成采集并正常退出。Linux 测试同时覆盖实际 SIGTERM 和进程内模拟信号；Windows 测试使用模拟信号，不等同于验证终端 Ctrl+C，且尚未实机验收。
- 写接口测试覆盖不同端口的同站请求和跨站请求，验证错误来源被拒绝；同时启动真实 Vite 代理，验证合法登录写请求正常转发。
- 调度建议确认测试覆盖省略请求体的情况，核对建议已确认且创建的待执行任务尚未分配员工。
- 还车定位时间测试覆盖无效日期、无时区、错误类型、超出 MySQL DATETIME 年份范围及有效边界：无效输入返回 400 且不写入证据；闰日和时区偏移转换正确，有效但过期的定位保留 UTC 时间。
- 调度和维修动作缺少必填请求体时返回 400；无请求体的调度开始、完成和取消仍进入正常业务检查。编号、道路及运营数值拒绝布尔值和数组，合法数字字符串仍可使用；测试核对无效请求不产生审计写入。
- 账户编号测试覆盖相邻的超范围编号、旧会话、安全整数上界及注册回滚。登录查询在数据库内保留精确编号，超范围账户不会签发会话；当前接口尚不支持完整的无符号 64 位编号。

## 性能样本

以下为隔离库中的单机样本，不代表生产并发或其他数据分布：

| 查询 | 数据与观察 |
|---|---|
| 个人订单分页 | 10 万订单、目标用户约占一成：增加 `(user_id,id)` 索引后，第一页执行计划由检查 1901 行变为读取 101 行，单次约 3.36 毫秒降至 0.76 毫秒；索引增加写入及存储开销 |
| 归还记录分页 | 50101 条记录：先确定分页编号再关联展示信息；样本中记录集中的用户读取 101 条，记录稀疏时仍可能扫描大量其他用户记录 |
| 支付与积分分页 | 各 50101 条记录：对比先选编号再回表后，支付查询原计划已按数据分布选择索引；积分查询替代方案改善稀疏用户但增加密集用户的回表工作，因此保留原查询 |
| 调度建议 | 1000 站点、2000 条拆分建议：需求按站点预聚合后，三轮约 216–265 毫秒，原查询约 2173–2429 毫秒；不包含建议保存。后续加入禁行站点优先调出后，在全部位于禁行区外的同规模样本交替查询四轮，新版约 225–252 毫秒，上版约 212–269 毫秒，结果一致；包含数据库结果传输 |

| 风险候选 | 10000 辆车、100 辆达到阈值：候选查询三轮约 73–75 毫秒，完整评分约 246–286 毫秒；不包含告警保存 |
