# 测试与验收说明

测试应在本机 MySQL 已启动且 `.env` 配置完成后执行。`npm test` 会重建 `campus_bike_test` 的测试数据；浏览器测试会在业务演示库中产生测试记录。

```text
npm run build
npm run format:check
npm test
npm start
npm run test:e2e
npm run check
```

浏览器测试需要另一个终端中保持 `npm start` 运行。备份与恢复需要本机 `mysql`、`mysqldump`，操作步骤见项目根目录说明。

## 本机验证记录

2026-10-27 在 Linux、Node.js 24.16.0 和 MySQL 8.0.46 上验证：89 项后端及数据库测试、12 项浏览器测试通过，构建和格式检查通过。桌面与手机宽度的 20 项页面检查没有发现页面错误或横向溢出。一次与数据库测试并行的浏览器测试因等待页面同步超时失败；数据库测试结束后顺序重跑，12 项通过。

测试覆盖并发借车、还车拒绝留痕、支付幂等及回滚、调度容量和库存快照、维修权限、风险处置、积分复核和冲销、排行隐私、热点筛选与时段裁剪、调整幂等冲突及余额不足，命名锁获取和释放异常、事务回滚及快照启动异常，跨时区时的北京时间筛选和曲线标签，抽样曲线的连续段与缺口，风险告警的工单时间边界与重复刷新去重、碳系数精度和旧库迁移，教学查询中借还时间的独立筛选，预设周期叠加站点、日期类型和小时筛选，以及使用已观测的边界外快照计算历史覆盖时长并排除未来快照。演示快照恢复到独立新库后，核对 18 张表、4 个视图、2 个触发器、37 个存储过程，15 项数据不变量均通过；新版恢复后的流水表和兼容视图保留八位小数的系数精度。

查询计划检查中，近一小时快照和近一日碳流水使用了时间索引；小样本下部分工单和调度查询由优化器选择扫描或主键路径。尚未进行生产规模负载测试，也未在 Windows 11 实机验收。截图、日志、备份和数据库快照属于本机生成文件，不提交至仓库。


## 热点查询样本性能

在隔离测试库中生成 6 个站点、每站 30 天每分钟一条的模拟快照，共 259,200 条。相同环境下，热点报表单次运行由约 8.8 秒降至约 5.8 秒，返回 6,876 个保留可借数量极值的曲线点；统计仍使用全部快照。测试结束后已删除临时测试库。该结果是本机单次对比，不代表生产负载或并发能力。

2026-10-27 增加曲线缺口识别后，在隔离库以 6 个站点、共 259,200 条连续采样作单次对比：增加前约 5.6 秒，增加后约 8.0 秒，均返回 3,600 个曲线点；增加的时间用于按完整采样计算连续段。该结果仅反映本机单次测试，不代表并发吞吐。

生成调度建议的需求读取在隔离库单次对比：6 个站点、259,200 条快照、2,000 笔模拟订单下，完整热点报表约 7.65 秒，仅查询库存和借还需求约 12 毫秒，两者需求和建议一致。该结果不包括建议写入耗时，不能代表生产并发性能。

## 风险刷新样本性能

隔离库中以 10 辆车、10,000 条历史工单进行单次测试，评分结果一致。旧版评分与工单读取约 28 毫秒，向后端传输 10,000 条工单；新版评分约 10 毫秒，首次完整刷新约 40 毫秒并传输新告警所需的 1,000 条工单，重复完整刷新约 21 毫秒并传输 0 条工单。完整刷新包含告警去重和写入，与单纯读取不能直接比较；结果仅反映本机单次测试。
