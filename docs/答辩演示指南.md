# 青行 Qingxing · 答辩演示指南

建议12–15分钟，先展示数据库设计，再用真实交互证明业务规则。开始前完成校园库初始化，确认 npm run build、npm test 与浏览器验收的实际输出；本指南是操作方案，不是通过证书。准备 node scripts/render-report.mjs 生成的 HTML 和 ER图.svg。演示前保存测试样本，操作后不重置正在检查的数据。

| 顺序 | 操作 | 讲解要点与证据 |
|---|---|---|
| 1 需求（1分钟） | 打开首页/报告，介绍校园问题 | 8实体、11命名行、13角色边；16物理表与支持表口径 |
| 2 ER（2分钟） | 打开独立SVG与结构页 | 起点/终点及调出/调入两角色；任务车辆M:N；待分配员工可空；报修人和维修人分别关联 |
| 3 学生闭环（3分钟） | 欧阳晨学生账号借可用车；圈外归还；合法归还；支付；重复支付 | 圈外仍RUNNING并留痕；合法变UNPAID；支付PAID且账本只一条；金额分、路线估算 |
| 4 调度（2分钟） | 贾鑫洋管理员创建建议任务，分配郑一凡；运维出发并完成 | 创建即预留目标车位；出发清位置；完成释放预留并落站；显示前后库存 |
| 5 维修（1分钟） | 王奕学生报修；管理员分配；郑一凡填写结果完成 | 同车一张活动工单；仅被分配员工处理；故障与维修时间可追溯 |
| 6 七创新（3分钟） | 热点、建议、风险、路线、碳积分、榜单、围栏逐项展示 | 热点显示采样覆盖；风险展示规则原因；路线可切换；碳系数模拟；榜单姓名脱敏 |
| 7 SQL与并发（2分钟） | 执行queries.sql；展示真实并发测试日志及对象列表 | 空异常结果结合样本；GET_LOCK是连接级要主动释放；触发器不代替所有跨表校验 |
| 8 恢复与局限（1分钟） | 展示独立campus_bike_restore_库核对日志 | 16表3视图2触发器1过程；不覆盖原库；地图、支付、规则模型均有边界 |

常见答辩问题：为什么11联系却画13条？两项双角色拆边。为什么8实体却16表？8业务实体+1关联+7支持。可空UNIQUE是候选码吗？不是全表候选码，只约束非空子集。是否所有表BCNF？需限定FD，生成列和记账快照不能无条件宣称。为何staff和users有姓名电话？当前保存员工时事务同步两表姓名和电话，是有意的联系信息副本；要说明更新一致性和跨表冗余。如何防超容？occupied+reserved联合校验与事务锁。是否真实GPS/支付/预测？都是明确标注的教学模拟或规则。

发生错误时保留页面反馈与服务器日志，核对权限、站点容量、活动订单和任务状态，不使用手工改数据库把失败伪装成功。无法现场完成的测试明确标为未验证。
